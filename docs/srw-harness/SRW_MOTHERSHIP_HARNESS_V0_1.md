# 超级机器人大战母舰 Harness v0.1

## 版本定位

SRW Mothership Harness v0.1 是第一版可执行母舰协议。它不负责替代项目代码，不负责全自动跑任务，也不负责让 AI 自己决定长期方向。

它负责三件事：

- 把复杂项目拆成驾驶员能判断的机体、接驳点和武器。
- 把 AI 的行动限制在可见、可批准、可验证的驾驶舱流程里。
- 把每次战斗复盘沉淀为下一次可复用的母舰资产。

v0.1 的核心口令：

```text
AI 可以推演路线，驾驶员决定出击。
AI 可以装填武器，驾驶员保留发射键。
AI 可以执行验证，战果必须回到驾驶舱显示。
```

## 母舰职责

母舰不是一个仓库，也不是一个自动任务目录。母舰是一套跨项目作战纪律。

母舰必须维护：

- 当前目标：这次到底要解决什么。
- 当前机体：本次主要操作哪个项目或模块。
- 当前接驳：是否涉及宿主楼层、世界书、数据库、UI、API 或跨项目协议。
- 当前武器：本次采用哪些可复用打法。
- 当前批准门：哪些动作可以直接执行，哪些必须驾驶员批准。
- 当前验证：怎么证明结果有效。

母舰不允许：

- 用自动化替代驾驶员判断。
- 把一次性任务伪装成长期框架。
- 在没有验证的情况下宣称成功。
- 在驾驶员没有批准时跨越剧情、协议、数据结构或生产状态边界。

## 一次出击流程

### 1. Briefing：战前简报

AI 在动手前应给出短简报：

- 任务目标。
- 主机体和可能被牵连的副机体。
- 已知不变量。
- 主要失败模式。
- 是否存在需要驾驶员批准的动作。

简报不需要长，但必须让驾驶员知道接下来会发生什么。

### 2. Recon：侦察

侦察阶段只读：

- 搜索相关文件。
- 读取边界文档。
- 确认当前 git 状态。
- 定位接口、状态、提示词、世界书、楼层或 UI 入口。
- 找出可执行验证方式。

侦察阶段可以直接执行，不需要批准。

### 3. Loadout：装载武器

AI 选择本次要用的 Arsenal 项，例如：

- 消息污染防线。
- 世界书裁剪。
- 同层桥接真实楼层。
- 模块分层。
- 驾驶舱批准门。

如果没有合适武器，AI 应明确说这是新打法，并在复盘时决定是否沉淀。

### 4. Approval：驾驶员批准

以下动作进入批准门：

- 改剧情方向。
- 改角色长期设定。
- 改跨项目协议。
- 改数据结构。
- 引入自动化。
- 删除、迁移、覆盖用户资产。
- 部署、推送、发布。

驾驶员批准后，AI 才能进入执行。

### 5. Sortie：出击执行

执行阶段遵循小步原则：

- 一次只改与目标直接相关的文件。
- 保持可回看 diff。
- 不顺手重构无关区域。
- 遇到新高风险边界时返回批准门。

AI 可以在可逆、局部、低风险范围内主动修正明显问题。

### 6. Verification：命中确认

验证必须尽量执行，而不是只靠阅读。

可用验证包括：

- 类型检查。
- 单元测试。
- 构建。
- 浏览器或 UI 检查。
- 关键词检索。
- 文档结构检查。
- 对宿主楼层、数据库、世界书桥接的最小链路验证。

如果不能执行验证，必须标明原因和残余风险。

### 7. Debrief：战后复盘

复盘输出三类内容：

- 已执行：实际改了什么、跑了什么。
- 已检查：读过什么、确认了什么。
- 仍是假设：没有验证或需要驾驶员后续判断的部分。

可复用经验进入 `ARSENAL.md`；新机体或接口进入 `UNIT_REGISTRY.md`。

## 驾驶舱输出格式

每次任务结束时，AI 应尽量按这个口径报告：

```text
已执行：
- ...

已验证：
- ...

未触碰：
- ...

需要驾驶员判断：
- ...
```

这不是为了格式漂亮，而是为了避免 AI 把“猜测”“检查过”“真的跑过”混在一起。

## v0.1 成功标准

第一版 SRW Mothership Harness 成功，不看自动化程度，只看五件事：

- 驾驶员能看懂当前在操作什么。
- AI 不再把母舰误写成 `.codex-loop`。
- 高风险动作会停在批准门前。
- 每个机体有登记边界。
- 每次复盘能沉淀一个更稳的打法。

## v0.1 禁止事项

- 禁止默认启动自动长跑。
- 禁止把 `.codex-loop` 当母舰核心。
- 禁止绕过宿主真实楼层做假同层状态。
- 禁止自动改长期剧情和角色关系。
- 禁止没有验证就宣称“完成可用”。
- 禁止删除或回滚用户未授权的工作树内容。

## 第一批适配目标

v0.1 只适配三类资产：

- `islandmilfcode`：主机体，负责手帐楼层、续写、变量、记忆库、剧情路由。
- `webgame-ui`：驾驶舱候选机体，负责更可视化、更游戏化的交互面板。
- `bridgeapi_shujuku`：接驳舱，负责把 UI 操作接回宿主真实楼层、世界书、数据库和生成链路。

更多项目可以接入，但必须先补机体登记，不能直接进入出击。
