# Cockpit Approvals

## 目的

驾驶舱批准门用于保护驾驶员的判断权。它不阻止 AI 干活，只阻止 AI 抢方向盘。

每次任务都先判断动作属于 A、B、C 哪一级。

## A 级：AI 可直接执行

A 级动作满足三个条件：

- 可逆。
- 局部。
- 不改变长期语义。

常见动作：

- 搜索文件、读取文档、定位接口。
- 新增解释性文档。
- 修正明显拼写、链接、标题层级。
- 运行已有测试、构建、类型检查。
- 生成检查清单或候选方案。
- 在同一职责文件内做小范围修复。

AI 执行前仍应简短说明意图，例如“我会新增一份文档，不碰代码”。

## B 级：AI 草拟，驾驶员批准后执行

B 级动作可能改变系统行为，但可通过审批和验证控制风险。

常见动作：

- 改 UI 主流程。
- 改提示词主口径。
- 改世界书触发规则。
- 改角色关系推进规则。
- 改状态结构或数据适配层。
- 新增跨模块接口。
- 引入新依赖。
- 把手操步骤封装成半自动工具。
- 批量更新文档或配置。

AI 在 B 级动作前必须提供：

- 推荐方案。
- 影响范围。
- 回滚方式。
- 验证方式。
- 为什么现在值得做。

驾驶员批准后才能执行。

## C 级：必须停火等待

C 级动作不可用默认判断代替驾驶员。

常见动作：

- 删除目录或批量删除文件。
- 回滚、覆盖、重置用户改动。
- 写入生产数据。
- 执行发布、推送、部署、合并。
- 改长期剧情事实。
- 改角色永久设定。
- 改存档语义。
- 改跨项目协议的权威版本。
- 启用无人值守自动化长跑。

C 级动作必须有明确驾驶员指令。指令只对当前动作有效，不自动授权同类后续动作。

## 剧情和角色批准门

SRW Harness 对剧情、角色、世界观采用更高保护级别。

AI 可以直接做：

- 总结现有设定。
- 找冲突。
- 草拟候选路线。
- 标注风险。
- 写非权威草案。

AI 必须等批准才能做：

- 把候选路线写入权威文档。
- 改角色长期关系。
- 改玩家路线变量含义。
- 改世界书常驻条目。
- 改影响存档解释的字段。

判断标准：如果改完之后“这个角色以后就该这么理解”，那必须驾驶员批准。

## 桥接和宿主批准门

涉及 `bridgeapi_shujuku`、同层卡、真实楼层、世界书和数据库时，默认 B 级起步。

AI 可以直接做：

- 读取桥接文档。
- 画出消息流。
- 写最小测试计划。
- 检查事件名、变量名、调用顺序。

必须批准：

- 改隐藏 real user / assistant 楼层策略。
- 改正则深度。
- 改数据库写入时机。
- 改 `/trigger await=true` 或生成链路。
- 改世界书扫描入口。

必须停火：

- 批量改真实聊天记录。
- 自动清理宿主楼层。
- 绕过宿主权威状态，用 iframe 状态冒充成功。

## 自动化批准门

自动化默认不属于核心能力，属于外挂。

允许直接自动化：

- 重复运行本地检查。
- 根据已批准模板生成报告草稿。
- 对文档做关键词一致性检查。

必须批准：

- 自动执行多步修改。
- 自动创建任务队列。
- 自动跨文件重写。
- 自动调用生成链路。

必须停火：

- 无人值守长跑。
- 自动删除、迁移、回滚。
- 自动修改剧情权威源。
- 自动发布、推送、部署。

## 驾驶员批准句式

为了减少误会，建议使用明确句式：

- “批准执行这一次。”
- “只批准改文档，不批准改代码。”
- “只批准侦察，不批准写入。”
- “批准 B 方案，不批准自动化。”
- “停，先复盘。”

AI 只能按字面批准范围行动。
