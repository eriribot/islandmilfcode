## 主模块：islandmilfcode

模块名：`islandmilfcode`

负责：

- 手帐式楼层阅读和续写。
- 回溯、重新生成、变量读取、状态驱动 UI。
- 手机、记忆库、剧情路由等主流程。

人能看到的界面：

- 手帐阅读器。
- 楼层正文区。
- 右键楼层菜单。
- 手机入口。
- 记忆库入口。
- 当前 Codex 工程线程。

主要输入：

- 宿主聊天楼层。
- `stat_data`。
- MVU 或酒馆变量 API。
- 用户输入。
- 世界书控制结果。
- 记忆库摘要和事件。

主要输出：

- 新楼层或重生成楼层。
- 状态更新。
- 变量写回。
- UI 渲染。
- prompt 拼装结果。
- 记忆库提交。

权威状态：

- 宿主消息楼层是剧情记录的权威。
- `stat_data` 是结构化状态主入口。
- 记忆库表保存长期事实和事件索引。

不能破坏的规则：

- `index.ts` 只做入口装配、初始化、生命周期绑定和渲染调度。
- 页面层不要直接操作底层变量接口。
- `prompt` / `message-format` 不写 DOM、不写变量。
- `render` 不直接触发生成请求。
- 重新生成成功清空 `draft`，失败保留 `draft`。
- `lastSummarizedIndex` 只前进，除非它超过实际消息总数。

常见失败：

- 业务逻辑继续堆进 `index.ts`。
- prompt、变量、动作、渲染互相串层。
- 角色名硬编码到到处都是。
- 摘要索引回退，旧消息污染 prompt。
- 世界书角色卡被关键词误触发。
- 重生成失败后草稿丢失。

可以直接做：

- 读文档、读接口、定位函数。
- 新增解释性文档。
- 小范围修正文档或测试。
- 运行类型检查、构建、关键词检查。

必须审查后做：

- 改 prompt 主结构。
- 改变量 schema。
- 改记忆库提交时机。
- 改楼层生成或回溯行为。
- 改角色路线推进规则。
- 大范围拆分 `index.ts`。

怎么验证：

- `rg` 检查职责边界和关键词。
- TypeScript 检查。
- 构建。
- 最小楼层交互测试。
- 重新生成成功 / 失败路径测试。
- 摘要污染回归测试。

相关经验：

- 模块边界。
- 消息污染防线。
- 世界书按代码判断加载。
- 艾尔登特审查门。

## 候选界面模块：webgame-ui

模块名：`webgame-ui`

负责：

- 更游戏化、更可视化的操作面板。
- 按钮、状态面板、模式切换和反馈。

权威状态：

- UI 本地状态不是剧情权威。
- 权威状态必须回到宿主楼层、变量、数据库、插件或明确的状态源。

不能破坏的规则：

- UI 只能显示和提交操作意图，不能自己宣布剧情完成。
- 高风险按钮必须让人确认。
- 失败状态必须看得见。
- 不能用漂亮界面掩盖没有接通。

必须审查后做：

- 接入真实生成链路。
- 接入真实数据写入。
- 改同层卡主交互。
- 增加自动连续执行。

怎么验证：

- 浏览器截图。
- 控制台错误检查。
- 按钮到宿主动作的链路检查。
- 失败状态显示检查。

## 宿主接通模块：bridgeapi_shujuku

模块名：`bridgeapi_shujuku`

负责：

- 把 UI 操作接回酒馆宿主真实聊天楼层。
- 让原生规划、数据库更新、世界书扫描和助手生成链路真正发生。

权威状态：

- `SillyTavern.getContext().chat` 或等价宿主聊天状态是权威。
- hidden real user / assistant 楼层承载原生链路。
- iframe 或本地 UI 状态只能作为显示，不能当最终事实。

不能破坏的规则：

- 同层操作必须经过真实宿主消息。
- 世界书扫描不能被 UI 缓存替代。
- 数据库更新必须能追溯到真实楼层或明确动作。
- 接通失败必须暴露给人，不能静默装成功。

必须审查后做：

- 改 hidden floor 策略。
- 改 `/trigger await=true` 调用方式。
- 改数据库写入时机。
- 改正则深度。
- 改世界书扫描入口。

怎么验证：

- 最小真实楼层往返。
- hidden user / assistant 楼层检查。
- 世界书命中检查。
- 数据库更新检查。
- 失败状态 UI 检查。
