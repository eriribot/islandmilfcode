```text
玩家输入自然剧情要求
→ 主 AI 写出本轮可见正文

→ 只保存有正文原句证据、日期合法的变化
→ 手机企划页立即显示正确进度
```

同时封住同一状态写入流程中“擅自创建未登记主线事件”的问题。

## 3. 下一轮允许修的问题

下一轮只能处理：

1. 把现有严格正文证据检查接到正常主正文成功完成后的生产流程。
2. 让检查只读取本轮新生成的可见正文，不读取玩家意图、规划文字、摘要自述或更早回合作为本轮证据。
3. 将通过日期和逐字证据检查的第七卷路线事实写入现有 memoryDB 存储，并走现有持久化流程。
4. 写入成功后刷新手机企划页，使 `0/2` 能按真实剧情变为 `1/2` 或 `2/2`。
5. 对普通状态整理输出的主线事件执行真实白名单检查，拒绝 `SAE_08-1` 等未登记事件。
6. 为上述行为补充合同测试、失败日志和最小真实酒馆 API 正反例证据。

## 4. 下一轮禁止碰的内容

下一轮不能修改：

- 五条路线的名称、含义、所需剧情条件和日期窗口。

- 游戏开发项目字段、行动数值、六天计划和结算规则。
- 已选路线进入后续正文的方式。
- 六天计划进入主 AI 正文的方式。
- 酒馆外层消息、hidden floor、`MESSAGE_SENT`、`/trigger`、shujuku、ACU、数据库插件或世界书扫描时机。
- 变量 schema、存档格式或现有路线选择存储格式。
- `package.json` 中失效的 `pnpm simulate:v07-routing` 便捷入口。
- 与本次失败无关的 UI 文案、关系数值、摘要系统和角色设定。

同时允许在普通状态整理结果写入前增加主线事件白名单拒绝逻辑。

## 6. 禁止改变或禁止触发的链

禁止改变：

- 主 AI 使用的酒馆预设、角色卡、世界书和正文上下文组装。
- 玩家输入与主正文生成的现有消息保存方式。
- 手机路线最终确认链。
- 游戏开发周结算链。
- 酒馆外层聊天楼层数量。

禁止新触发：

- 真实宿主 user / assistant 楼层。
- `MESSAGE_SENT`。
- `/trigger`。
- shujuku / ACU / 数据库更新钩子。
- 因路线事实检查而再次生成一段玩家可见正文。

严格路线检查必须是静默状态检查，不能污染玩家正文。

## 7. 必须保留的规则

1. 自由输入永远不能直接替玩家确认最终路线。
2. 路线事实只能来自本轮 AI 可见正文中的连续原句证据。
3. 一句“我想独立”“以后也许自己做游戏”不能增加进度。
4. 日期早于某项条件开放日时，不能提前写入。
5. 已成立的路线事实不能被 AI 静默降回未成立。
6. 严格检查失败时，不得写入部分结果。
7. 最多按现有设计重试一次；仍失败时留下可见诊断，但主正文不能丢失。
8. 路线条件写入不能改动玩家关系数值、物品或主线事件。
9. 未登记的主线事件必须拒绝，不能因为模型输出就创建。

## 10. 必须提供的真实运行证据

自动检查通过后，仍必须在 `http://127.0.0.1:8000/` 使用酒馆当前 API 重跑两条短输入。

反例：

```text
（测试）时间跳转到2013-03-04。我只是想到以后也许自己做游戏，现在没有退出社团，也没有交接任何工作。请写出这只是想法，还没有行动。
```

预期：`0/2`，没有自动选路线。

正例：

```text
（测试）时间跳转到2013-03-04。因为伦也的失误让社团分崩离析，我把剩余文件和钥匙交给伦也，退出共享账号并正式离开；随后以自己的名义登记新社团，支付第一笔开发费用，开始独立制作游戏。请写出交接完成和退出正式生效。没有任何人跟随我离开。
```

预期：

- 可见正文明确写出交接和退出已经完成。
- 企划页变为 `2/2`。
- 页面只开放玩家确认，不自动选择。
- 不出现 `SAE_08-1`。
- 刷新或重载同一存档后仍为 `2/2`。
- 酒馆外层聊天楼层数不因严格检查而增加。

必须保留：输入、生成正文关键句、企划页截图、状态检查日志、控制台错误和外层楼层数前后对比。
