# 最近 16 层懒加载使用说明 v0.1

## 玩家怎么用

使用方式和以前一样，不需要打开设置，也不需要重新建档：

1. 在标题页直接打开原来的存档。
2. 进入后会先看到最新的楼层。
3. 一直往前翻，到这一批最前面时，游戏会自动读取再前面的 16 层。
4. 往后翻到边界时，也会自动读取相邻的 16 层。
5. 想继续发送正文时直接发送即可；如果当时正在看旧楼层，游戏会先自动回到最新楼层再发送。

## 这次改变了什么

以前打开高楼层存档时，会把全部正文一次性读进来。同一个索引和正文块在打开过程中还可能被重复读取。

现在普通打开只读取存档状态和最近 16 层。旧正文仍完整保存在存档里，只有翻到边界时才按每批 16 层取出。刚读取过的索引和正文块会短暂复用，不再马上重复读取。

楼层编号仍然是整个存档的真实编号。例如只加载了第 985 至 1000 层，界面仍显示第 985 至 1000 层，不会误显示成第 1 至 16 层。

## 哪些地方用了懒加载

- 普通打开存档：只加载最近 16 层正文。
- Reader 前后翻页：到边界才加载相邻 16 层。
- 提示词：继续使用原有的近期正文滑动窗口，不读取全部历史。
- 自动摘要：只按摘要游标读取下一小段需要的正文，不为摘要切换当前 Reader 页面。
- v3 恢复：正文、摘要和记忆都从存档对象恢复；所有正文只在 `#0` 的游戏 iframe 内显示，不创建宿主聊天楼层。

## 哪些操作仍会读取完整历史

导出完整备份、编辑旧正文、删除、回滚和存档维护属于明确的全历史操作。它们为了保证结果正确，仍可能扫描完整历史。这不影响普通打开和日常翻页已经变成懒加载。

## 对高楼层存档的预期

楼层越高，普通打开的改善越明显，因为首次进入不再把几百或几千层正文全部搬进内存。当前结论来自源码静态检查；100、1000、3000 层的真实耗时和内存数据尚未实测，不能先写成已经提速多少倍。

如果某一批旧楼层损坏或暂时读不到，界面会保留当前页面并提示失败，不会用这 16 层覆盖完整存档。
