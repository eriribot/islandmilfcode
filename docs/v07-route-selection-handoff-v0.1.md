# V07 路线选择阶段交接 v0.2

> 修订日期：2026-07-12（Asia/Shanghai）  
> 本版替代同文件的 v0.1 需求模型。  
> 状态：需求已由用户重新确认，等待按“一次一个文件”实施。  
> 本轮只更新交接文档，不修改生产代码。

## 1. 用户确认的领域模型

V07 必须拆成三个互不混淆的层级：

```text
有限期路线事实检查器
→ 只辅助记录第七章内已经发生的剧情事实

SAE_07-8 结束后的 DDL
→ 强制玩家在三条路线中亲自选择

路线选择的下游效果
→ 单飞、朱音分别打开对应游戏开发模式
```

路线事实检查器不拥有路线选择权，也不是路线 eligibility 守门器。

即使检查器被玩家关闭、副 API 调用失败、漏判，或者所有事实仍为 `0`，玩家在 DDL 到来后仍然可以选择任意路线。

## 2. 路线事实检查器的时间边界

检查器只在第七章的有限时间窗内运行：

```text
下界：2013-02-08（SAE_07-1 / 第七章开始）
上界：2013-03-04（不包含）
```

等价判断：

```ts
currentDate >= '2013-02-08' && currentDate < '2013-03-04'
```

因此：

- `2013-02-07` 及更早：不运行。
- `2013-02-08` 至 `2013-03-03`：可以运行。
- 进入 `2013-03-04`：立即关闭，不再发起路线事实副 API。
- `2013-03-04` 之后：不会因为仍未选择路线而重新打开检查器。
- 玩家设置中的“自动路线事实核对”只控制这个有限期检查器，不控制 DDL 和最终选择。

各 flag 的 `earliestDate` 仍可限制某项事实最早何时写入，但任何 flag 都不能成为最终选择按钮的硬资格条件。

## 3. 三条最终路线

玩家最终面对的是三条路线家族：

1. 留下。
2. 单飞。
3. 朱音。

玩家选择的是路线家族，不是在企划页面对五个内部 variant。

现有 `stay_blackgold`、`stay_user_only`、`solo_user_exit`、`solo_group_exit_except_tomoya` 等细分状态可以作为剧情事实、后续叙事配置或迁移资料继续评估，但不得继续作为五个并列的玩家最终选择按钮。

路线事实可以用于：

- 给玩家展示此前剧情形成了什么倾向。
- 给后续正文提供背景。
- 给单飞或朱音游戏开发模式提供具体配置。

路线事实不能用于：

- 禁止玩家选择某条路线。
- 自动替玩家选择路线。
- 因为副 API 没运行而把 DDL 卡死。

## 4. DDL 不由日期单独触发

`2013-03-04` 是 DDL 日期，但不能在进入当天、事件正文尚未完成时立刻弹出路线选择。

强制选择必须等待 `SAE_07-8` 的真实生命周期结束：

```text
当前日期到达 2013-03-04
→ SAE_07-8 被激活为进行中
→ 主正文完成 SAE_07-8 场景
→ 正文后 progress 对事件结束进行结构化提交
→ 写入 mainEvents['SAE_07-8'] = '已结束'
→ 清除 currentMainEventId 中的 SAE_07-8
→ 状态保存成功
→ 若 choice 仍为空，进入强制路线选择状态
```

不能采用：

```text
currentDate === '2013-03-04'
→ 直接强制选择
```

否则会在毕业典礼/美术准备室事件开始前抢走正文生命周期。

## 5. SAE_07-8 当前如何被确认结束

### 5.1 剧情库合同

`剧情第七卷.json` 为 `SAE_07-8` 声明：

- 触发日期：`2013-03-04`。
- 前置事件：`SAE_07-7`。
- 十段结束条件以英梨梨重新完成叶巡璃、诗羽确认创作突破、二人约定一起击退朱音收束。
- 结束后事件状态：`已结束`。
- 可接续事件：空数组。

因此 `SAE_07-8` 是 V07 当前事件链的单日叶子事件。

### 5.2 生产写入链

当前事件结束不是由前端按钮直接改状态，而是走正文后的结构化状态链：

```text
主正文成功
→ runSecondaryProgressUpdate()
→ parseProgressUpdate()
→ sanitizeProgressAgainstPlotLibrary()
→ applyProgressUpdate()
→ statusData.world.mainEvents
→ statusData.world.currentMainEventId
→ adapter.save() / persistConversation()
```

只有这条链正式接受并保存了终态，DDL 才能认为事件已经结束。

### 5.3 当前阻塞缺陷

`sanitizeProgressAgainstPlotLibrary()` 当前只在以下任一条件成立时允许当前事件写终态：

1. 当前日期已经晚于事件窗口结束日。
2. 当前事件存在已经可以激活的后继事件。

`SAE_07-8` 在 `2013-03-04` 当天不满足第 1 条，并且 `可接续事件` 为空，不满足第 2 条。

所以当前真实结果是：

```text
SAE_07-8 正文在 2013-03-04 当天完成
→ progress 提议 SAE_07-8:已结束
→ same-window terminal guard 拒绝
→ SAE_07-8 继续保持进行中
→ DDL 永远不能合法触发
```

实施 DDL 前必须先修通这个生命周期缺口。

允许结束 `SAE_07-8` 的判断必须至少同时满足：

```text
写入前 currentMainEventId === 'SAE_07-8'
且写入前 mainEvents['SAE_07-8'] === '进行中'
且当前日期 === '2013-03-04'
且本轮主正文已经成功完成
且正文后 progress 明确提交 SAE_07-8 的终态
且 currentMainEventId 同轮被清空
```

不得因为打开企划页、到达日期或单独点击路线按钮而伪造 `SAE_07-8:已结束`。

## 6. 强制选择的派生条件

强制选择状态应由权威状态派生，不另存一个容易漂移的布尔值：

```ts
routeChoiceRequired =
  currentDate >= '2013-03-04' &&
  isFinishedMainEventStatus(mainEvents['SAE_07-8']) &&
  currentMainEventId !== 'SAE_07-8' &&
  activeRouteChoice === null;
```

其中 `isFinishedMainEventStatus()` 继续接受现有终态集合：

```text
已结束 / 已完成 / 跳过 / 延后
```

正常 SAE_07-8 正文完成路径应写 `已结束`。`跳过/延后` 是否允许直接进入路线 DDL，实施时必须按事件跳过规则单独测试，不得只靠正则名称假定体验正确。

## 7. 强制选择的交互规则

当 `routeChoiceRequired === true`：

- 自动打开三线路线选择界面。
- 玩家可以暂时关闭界面查看刚完成的正文。
- 在 choice 成功提交前，禁止发送下一条主正文输入。
- 页面必须持续显示“完成路线选择后继续”。
- 重载同一存档后仍从权威状态重新派生并再次要求选择。
- 不新增宿主 user/assistant 楼层。
- 不触发 `MESSAGE_SENT`、`/trigger`、shujuku、ACU 或数据库插件。

玩家点击任意路线时仍需二次确认。确认成功后写入正式 choice receipt 并立即持久化。

## 8. 游戏开发开关

路线选择和游戏开发开关必须分层：

```text
choice = stay
→ 不自动开启当前单飞/朱音游戏开发模式

choice = solo
→ 开启单飞游戏开发模式

choice = akane
→ 开启朱音游戏开发模式
```

不能继续采用“任何有效 choice 都进入同一个游戏开发页面”的现有行为。

单飞和朱音的具体行动、参与者、时间窗与正文注入仍由各自游戏开发合同管理；不能从 family 名自动推导固定成员。

## 9. 回退合同

路线 choice 发生在 `SAE_07-8` 结束之后，因此必须服从楼层因果关系：

- 回退后 `SAE_07-8` 仍为已结束，且路线确认动作仍位于保留时间线内：choice 保留。
- 回退到 `SAE_07-8` 结束前：choice 必须失效，强制选择状态也暂时消失。
- 玩家重新完成 `SAE_07-8` 后：再次触发 DDL，可以重新选择三条路线中的任意一条。
- 回退后重新选择同一条单飞或朱音路线：不能复活旧确认实例的游戏开发进度。
- 不允许通过完整复制 memoryDB 到每个楼层实现。

回退技术模型将在后续文件实施前单独核准；不得再使用会在重载时变化的 `UiMessage.id` 作为唯一因果锚点。

## 10. 实施顺序：一次一个文件

后续严格按用户要求执行：每次只修改一个文件，交用户检查后再申请下一个文件。

推荐顺序：

1. `actions/index.ts`：修通 `SAE_07-8` 在 2013-03-04 当天通过真实 progress 合法结束的生命周期；不在此文件实现路线 UI。
2. `plot-state-machine/v07.ts`：把检查器窗口改成第七章开始至 `2013-03-04` 上界不包含。
3. `plot-state-machine/types.ts`：把玩家最终 choice 合同收敛为 `stay / solo / akane` 三条 family，并保留必要旧存档兼容类型。
4. `plot-state-machine/choice.ts`：删除 flag eligibility 对玩家选择的硬拦截，保留手动来源、DDL 生命周期和锁定检查。
5. `plot-state-machine/resolver.ts`：事实只计算提示/倾向，不再决定三条路线能否点击。
6. `plot-state-machine/memory.ts`：正式提交三线 choice receipt 和回退清除记录。
7. `phone/render.ts`：渲染三线选择与 DDL 阻塞提示，不显示五个最终 variant 按钮。
8. `index.ts`：绑定选择交互、二次确认、下一回合提交阻塞和持久化。
9. `state/store.ts`：实现 choice 与楼层的因果回退，不复制完整 memoryDB。
10. `game-development/index.ts`：只有 `solo / akane` 开启对应模式，并绑定新的 confirmationId。

若某一步实际需要先调整一个依赖文件，必须在修改前说明原因并等待用户批准。

## 11. 中文注释合同

所有新增或修改的关键生产逻辑必须包含中文注释，至少解释：

- 路线事实检查器为什么在 `2013-03-04` 上界关闭。
- 为什么副 API 结果不能限制玩家三线选择。
- 为什么 DDL 必须等待 `SAE_07-8` 真正结束。
- 为什么单飞、朱音是游戏开发开关，而留下不是默认开关。
- 为什么回退不能依赖临时 `UiMessage.id` 或完整 memoryDB 快照。

注释应说明领域原因和失败模式，不只把代码逐字翻译成中文。

## 12. 自动合同

实施完成后至少需要保护：

### 12.1 检查器窗口

- `2013-02-07`：不调用路线事实副 API。
- `2013-02-08`：允许调用。
- `2013-03-03`：允许调用。
- `2013-03-04`：不调用。
- 玩家关闭检查器：不调用，但不影响后续 DDL。

### 12.2 SAE_07-8 生命周期

- 日期到达但事件未结束：不要求选择。
- 事件仍为进行中：不要求选择。
- 同日合法 progress 提交 `已结束` 并清空当前事件：提交成功。
- progress 被 guard 拒绝或保存失败：不要求选择。
- 事件终态已持久化：才允许进入 DDL。

### 12.3 强制三线选择

- 三条路线始终都能由玩家选择，不受 flag 数量限制。
- 没有选择时不能发送下一段主正文。
- 选择只能来自企划页专用操作和二次确认。
- 刷新后 choice 保留。
- 自由输入和副 API 都不能自动生成 choice。

### 12.4 游戏开发

- `stay` 不自动开启单飞/朱音开发模式。
- `solo` 只开启单飞模式。
- `akane` 只开启朱音模式。
- 回退并重新确认同一路线时，不读取旧 confirmationId 的开发进度。

## 13. 人工验收边界

自动检查只能证明候选实现符合代码合同，不能代替玩家正文验收。

最终需要玩家使用可回退存档检查：

- `SAE_07-8` 正文没有被 DDL 提前打断。
- 事件结束提交后才出现三线选择。
- 路线检查器关闭/失败时仍能选择任意路线。
- 未选择时确实不能继续正文，但仍能查看刚完成的事件内容。
- 三条路线的二次确认与刷新持久化。
- 单飞和朱音分别开启正确游戏开发模式。
- 回退到事件结束前后两侧时 choice 与 DDL 状态正确。

在人工验收表填写前，只能称为“候选实现”。
