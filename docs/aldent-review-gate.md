# 艾尔登特审查门说明

## 目的

艾尔登特审查门解决一个很现实的问题：

> AI 改完以后，到底谁确认它真的可用？

答案是：人确认。

AI 负责产出、说明、测试和暴露风险；人负责审查、决定是否接受、决定下一轮修什么。

## 一轮工作怎么走

1. 先写清楚本轮任务。
2. AI 只改本轮允许改的文件。
3. AI 列出改了什么、怎么测试、还有什么风险。
4. AI 发出艾尔登特审查邀请。
5. 人填写审查表。
6. 人把问题分成必须修、应该修、以后再说。
7. 下一轮 AI 只能处理人批准的问题。

## 常用词

| 名称 | 白话解释 |
| --- | --- |
| 任务说明 | 本轮到底要做什么。 |
| AI 修改步骤 | AI 这一轮实际改文件。 |
| 审查邀请 | AI 改完以后，请人来看的说明。 |
| 人工审查 | 人检查体验、代码和接通情况。 |
| 下一轮修复清单 | 人允许下一轮 AI 修的问题。 |
| 下一轮范围 | 下一轮能碰什么、不能碰什么、怎样算修完。 |

## 硬门槛

- 没有人工审查表，不开下一轮。
- 没有可复现测试步骤，不能当作外部可验证成果。
- 体验审查低于 `30/50`，不能当作面向用户的版本。
- 代码结构低于 `30/50`，不能当作可维护实现。
- 接通审查低于 `30/50`，不能说已经真实接通。
- 只是演示页面，不能说已经接上真实数据库、插件或宿主流程。

## 分数解释

每类审查 `0-50` 分，总分 `0-150`。

| 总分 | 解释 |
| --- | --- |
| 135-150 | 可以给外部用户或更大范围测试。 |
| 120-134 | 很接近可用，只剩小修。 |
| 100-119 | 可用原型，还要继续迭代。 |
| 75-99 | 内部演示，不适合对外。 |
| 75 以下 | 本轮失败，不应发布。 |

## AI 可以做什么

- 读文件、定位接口。
- 按批准范围改文件。
- 跑测试、构建、关键词检查。
- 总结改动。
- 标出风险。
- 发出审查邀请。
- 把人的审查意见整理成候选修复清单。

## AI 不能做什么

- 自己宣布验收通过。
- 没有人审查就开下一轮。
- 擅自扩大下一轮范围。
- 页面只是演示，却说已经真实接通。
- 把失败状态藏起来，只展示成功样子。

## 人要决定什么

- 这个成果有没有解决用户真正要的事。
- 哪些问题必须下一轮修。
- 哪些问题先不碰。
- 下一轮是否允许开始。

## UI / 同层卡 / 数据接通规则

只要涉及 UI、手机页面、同层卡、数据库、插件或宿主聊天流程，都必须标明当前状态：

- 只是界面草图
- 只是本地状态演示
- 已接入真实状态读取
- 已接入真实状态写入
- 已可作为正式流程使用

这是事实标签，不是宣传词。

## 和自动任务的关系

自动任务只能执行已经通过人工审查的修复清单。

自动任务不能替人审查，也不能自动扩大范围。
