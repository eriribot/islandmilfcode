# 艾尔登特审查门

艾尔登特审查门是一套给 AI 协作开发用的人工审查流程。

它只守一条底线：

> AI 改完文件以后，不能自己宣布“完成”。必须请人审查。人的审查结果再变成下一轮要修的清单。

## 核心原则

AI 可以写代码、改文档、跑测试、总结风险。

但 AI 不能替人做最后验收。

这个流程的“钢之魂”是三句话：

- 不偷跑：没有人的审查，不开下一轮。
- 不自证：AI 的自检只能当参考，不能当验收。
- 不装通：只是页面演示，就不能说已经接上真实数据库、插件或宿主流程。

## 标准流程

```text
任务说明
-> 查艾尔登特组件清单
-> 查模块登记表
-> AI 修改文件
-> AI 列出改动和测试方法
-> AI 发出艾尔登特审查邀请
-> 人检查体验
-> 人检查代码结构
-> 人检查是否真的接通数据/插件/宿主流程
-> 人写出下一轮允许修的问题
-> 下一轮 AI 只修这些问题
```

## 硬规则

没有人工审查表，就没有下一轮。

AI 可以说“我跑了构建”“我检查了这些文件”“我认为风险在这里”，但不能说“我已经替你验收通过”。

## 三类审查

1. 体验审查：用起来对不对、清不清楚、有没有解决用户要的事。
2. 代码结构审查：文件放得对不对、职责清不清楚、后面好不好维护。
3. 接通审查：只是 UI 样子，还是已经真的读写状态、数据库、插件或宿主聊天流程。

每类 `0-50` 分。分数解释见 [aldent-review-gate.md](aldent-review-gate.md)。

## 和 SELF-CHECK 的区别

SELF-CHECK 是人自己的复盘和执行记录。

艾尔登特审查门是用来审查 AI 改出来的文件成果。

不要把这两件事混在一起。AI 的自检不是人工审查。

## 接通状态必须说清楚

做 UI、同层卡、手机页面、数据库、插件、宿主聊天流程时，必须标清当前状态：

- 只是界面草图
- 只是本地状态演示
- 已接入真实状态读取
- 已接入真实状态写入
- 已可作为正式流程使用

如果只是演示，就说只是演示。不要把“看起来能用”说成“已经真正接通”。

## 和 `.codex-loop` 的关系

`.codex-loop` 可以作为执行工具，但不能替代审查。

只有当人工审查表写出“下一轮允许修的问题”以后，才允许让下一轮 AI 继续执行。
