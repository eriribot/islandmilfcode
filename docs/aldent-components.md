# 艾尔登特组件清单

## 目的

组件清单说明艾尔登特每一轮工作要先看哪些东西、怎么决定能不能动手、改完以后怎么交给人审查。

它不替代项目代码，也不替代人的判断。它只让 AI 的行动保持清楚、可检查、能接续。

## 核心口径

```text
AI 可以分析路线，人决定是否进入下一步。
AI 可以执行修改，验收必须回到人工审查。
AI 可以跑检查，检查结果必须说清楚是通过、失败，还是没有跑。
```

## 六个组件

### 1. 本轮目标

本轮到底要解决什么。

要写清：

- 用户要的结果。
- 这轮允许碰的文件或模块。
- 这轮明确不碰的内容。

### 2. 主模块

本轮主要操作哪个模块。

先查 [module-registry.md](module-registry.md)。如果模块没有登记清楚，可以先读、先分析、先写文档，但不要直接做跨模块改动。

### 3. 接通点

本轮是否碰到真实状态来源。

常见接通点：

- 手机 UI。
- prompt 拼装。
- 记忆库。
- 变量读写。
- 数据库。
- 插件。
- 宿主聊天楼层。
- 世界书或角色卡加载。

只要涉及接通点，必须说清楚当前状态：

- 只是界面草图
- 只是本地状态演示
- 已接入真实状态读取
- 已接入真实状态写入
- 已可作为正式流程使用

### 4. 经验选择

先查 [experience-library.md](experience-library.md)，只选择本轮真正需要的经验。

不要为了显得完整而套模板。经验必须服务于当前风险。

### 5. 审查门

改完文件以后，必须发出艾尔登特审查邀请。

没有人工审查表，不开下一轮。

### 6. 验证

验证尽量用实际执行，而不是只靠阅读。

可用验证：

- TypeScript 检查。
- 构建。
- 单元测试。
- 关键词检查。
- 浏览器截图或交互检查。
- 最小真实链路检查。

不能跑的检查要说明原因。

## 一轮工作流程

```text
确认本轮目标
-> 查主模块登记
-> 判断接通点
-> 选择必要经验
-> 在范围内改文件
-> 跑能跑的验证
-> 发出审查邀请
-> 等人工审查表
-> 下一轮只处理人工批准的问题
```

## 不允许的事

- 没有人工审查就开启下一轮。
- 页面只是演示，却说已经接通真实状态。
- 擅自扩大到变量 schema、prompt 主结构、数据库写入时机或长期剧情规则。
- 把 AI 自检当成人工验收。
- 为了保留旧说法而留下不适合当前项目的隐喻。

## 结束报告

每轮结束至少说清：

```text
已修改：
已验证：
未触碰：
当前接通状态：
已知风险：
需要人工审查：
```
